# 移动端数据源面板滚动优化

## 目标

解决移动端设置面板中数据源区域的滚动冲突问题，提升移动端操作体验。

## 当前问题

用户反馈：在移动端操作设置数据源面板时，面板内部的滚动与外层页面滚动混在一起，导致操作体验不佳。

### 技术分析

通过代码分析发现根本原因：

1. **嵌套滚动容器**
   - 设置面板本身：`#settingsPanel` 有 `overflow-y-auto`（`index.html:152`）
   - 数据源区域内部：`.datasource-scroll-area` 也有滚动（`index.html:177`）
   - 两层滚动容器导致触摸事件冲突

2. **现有修复不足**
   - `css/mobile-optimize.css:1456-1471` 有针对滚动的修复
   - 使用了固定高度 `max-height: 40vh` 和 `overflow-y: auto`
   - 但仍然存在滚动冲突问题

3. **相关文件**
   - `index.html` 第 152-187 行：设置面板结构
   - `index.html` 第 177-181 行：数据源滚动区域
   - `css/mobile-optimize.css` 第 1456-1471 行：移动端滚动修复
   - `css/styles.css` 第 1475-1495 行：数据源区域样式

## 需求

### 功能需求

1. **解决滚动冲突**
   - 移除嵌套滚动，使用统一的面板滚动
   - 或者使用 CSS 属性（`overscroll-behavior`, `touch-action`）隔离滚动事件
   - 确保用户可以流畅地滚动查看所有数据源

2. **保持现有功能**
   - 数据源选择功能不变
   - 批量操作功能不变
   - 自定义 API 功能不变
   - 桌面端布局和功能不受影响

3. **符合移动端面板模式**
   - 遵循 `.trellis/spec/frontend/mobile-panel-pattern.md` 规范
   - 使用现有的 `mobile-panel-gestures.js` 系统
   - 保持与其他面板（历史记录、选集）的一致性

### 非功能需求

1. **性能**
   - 滚动流畅，60fps
   - 无卡顿或延迟

2. **兼容性**
   - 支持主流移动浏览器（Chrome, Safari, Firefox）
   - 支持不同屏幕尺寸（320px - 640px）

3. **可访问性**
   - 保持键盘导航支持
   - 保持屏幕阅读器支持

## 解决方案（建议）

### 方案 1：移除内部滚动区域（推荐）

**实施步骤**：
1. 移除 `.datasource-scroll-area` 的固定高度和 `overflow-y-auto`
2. 让数据源列表自然展开，由外层面板统一滚动
3. 调整面板内容布局，确保所有内容可见

**优点**：
- 彻底解决嵌套滚动问题
- 实现简单，风险低
- 符合移动端单一滚动容器的最佳实践

**缺点**：
- 数据源列表较长时，面板内容会很长

### 方案 2：使用 CSS 隔离滚动事件

**实施步骤**：
1. 在 `.datasource-scroll-area` 上添加 `overscroll-behavior: contain`
2. 添加 `touch-action: pan-y` 限制触摸方向
3. 确保滚动事件不会传播到外层

**优点**：
- 保持现有布局结构
- 修改最小化

**缺点**：
- 浏览器兼容性需要测试
- 可能仍有边缘情况

### 方案 3：参考已有提案，重构为卡片化设计

**参考**：`openspec/archive/mobile-datasource-card-redesign/proposal.md`

**实施步骤**：
1. 将数据源列表改为卡片式布局
2. 增大触摸目标（≥ 44x44px）
3. 移除内部滚动，使用统一滚动
4. 优化视觉层次和交互反馈

**优点**：
- 全面提升移动端体验
- 解决多个已知问题（触摸目标小、视觉反馈不足等）

**缺点**：
- 改动较大，需要更多测试
- 开发时间较长

## 验收标准

### 必须满足

- [ ] 移动端滚动流畅，无冲突
- [ ] 可以轻松滚动查看所有数据源
- [ ] 数据源选择功能正常
- [ ] 批量操作功能正常
- [ ] 自定义 API 功能正常
- [ ] 桌面端功能和布局不受影响

### 测试场景

#### 场景 1：滚动数据源列表
**Given**: 用户在移动端打开设置面板
**When**: 在数据源区域向上/向下滑动
**Then**:
- 滚动流畅，无卡顿
- 不会触发外层面板滚动
- 可以滚动到列表顶部和底部

#### 场景 2：选择数据源
**Given**: 用户在移动端查看数据源列表
**When**: 点击任意数据源复选框
**Then**:
- 复选框状态正确切换
- 已选数量正确更新
- 不会因为滚动而误触

#### 场景 3：桌面端不受影响
**Given**: 用户在桌面端打开设置面板
**When**: 操作数据源设置
**Then**:
- 布局和样式与之前一致
- 所有功能正常工作

## 技术约束

1. **必须使用现有技术栈**
   - Pure JavaScript (ES6+)
   - Tailwind CSS
   - 不引入新的库或框架

2. **必须兼容现有系统**
   - 使用 `mobile-panel-gestures.js` 系统
   - 保持 localStorage 数据结构不变
   - 保持 API 配置结构不变

3. **必须遵循前端规范**
   - 遵循 `.trellis/spec/frontend/` 下的所有规范
   - 特别是 `mobile-panel-pattern.md` 和 `quality-guidelines.md`

## 实施建议

推荐使用**方案 1（移除内部滚动区域）**，原因：
1. 实现简单，风险低
2. 彻底解决问题
3. 符合移动端最佳实践
4. 可以快速验证效果

如果方案 1 效果不理想，可以考虑方案 3（卡片化重构），但需要更多时间。
